# Real weights on RunPod — 2026-11-25

FastH3 V2 (`FastVideo/FastVideo-FastH3-8-Step-V2`, the `h3-8step` bundle on the
`fv-weights-h3-ltx-500` volume: bf16 transformer, MiniMax-H3 VAE and audio VAE) and
`taeh3.safetensors`, exported and run on a RunPod pod: RTX 4090 24 GB, 32 vCPU, 124 GB RAM,
Ubuntu 24.04. Software: litert-torch 0.8.0, ai-edge-litert 2.1.2, torch 2.9.1+cu128.
The pod was driven with `scripts/runpod/{pod,remote}.py`; every number below is from the
`out-N.log` files of that session. The fastwan-litert run of the same day is in
`fastwan-litert/docs/runs/`.

## Export

`h3-litert export --variant fasth3-v2 --model-dir /workspace/weights/h3-8step --tae
taeh3.safetensors --size 256x256x22 --weights f16 --jobs 4`

| part | graphs | size | wall (4 workers, the pod shared with two other jobs) |
|---|---|---|---|
| text refiner, buckets 128 / 256 / 512 / 1024 rows | 4 | 4 × 1 597 MB | 252–320 s each |
| embeds, heads | 4 | 3 MB | 4–7 s each |
| DiT block (qkv + post), per block in a worker | 100 | FILL_BLOCK_MB | qkv 47–120 s, post 75–114 s |
| attention, VAE decoder / encoders, audio VAE, TAEH3 | FILL_TAIL_N | FILL_TAIL_MB | FILL_TAIL_S |
| whole export | FILL_TOTAL_N | FILL_TOTAL_GB | FILL_TOTAL_T (two runs, see below) |

Three things this export taught the exporter:

- **bf16 shards.** safetensors' numpy reader refuses bf16; both ports now read checkpoints
  through the torch reader.
- **The f16 flag.** The first run wrote dynamic-range int8 graphs under the f16 label (the
  converter flag was passed as a dotted key); it was stopped at 36 files and restarted with the
  nested flag. Details in the fastwan-litert report of the same day.
- **A 61 GB cgroup.** `free` shows the host's 124 GB, but the pod's memory cgroup is 61 GB
  (`memory.limit_in_bytes`), and the OOM killer took worker processes mid-block (each worker
  peaks at 10–13 GB converting one 280M-parameter block; four of them plus the other jobs on the
  pod crossed the line). `multiprocessing.Pool` then waits forever for the lost tasks. The
  exporter now watches its workers, restarts the pool for the missing blocks, and has
  `--resume`, which skips every graph already on disk (the 39 GB of finished graphs were kept;
  the 7 missing blocks and the tail graphs were converted by a second run with `--jobs 3`).

## GPU accelerator notes (ai-edge-litert 2.1.2 on Linux, WebGPU backend)

The tiny fixture's graphs compile on the GPU except `vae_enc_*`, `vae_dec_out` (Conv3D /
the 3-D unpatchify), `avae_dec_*` (the batch-folded 1-D transposed convolutions) and
`taeh3_*`; `Graph` falls back to the CPU interpreter per graph, so `--accelerator gpu` runs
end to end with those parts on the CPU.
